# 옛썰 설문 등록 · 설문 응답 흐름 개선 – 개발 핸드오프

`designs/` 폴더의 `.dc.html` 파일은 디자인 시안 원본이에요. 레이아웃·색·문구·인터랙션 참고용이고, 그대로 실행되는 코드는 아니에요. 우리 앱 스택과 기존 컴포넌트에 맞게 다시 구현해 주세요.
시안 속 이미지 경로(`/_blob/...`)는 캔버스 전용이라, 실제로는 `assets/` 폴더의 PNG를 쓰면 돼요.
제목·문항·포인트·인원은 모두 예시 데이터예요.

## A. 설문 등록 (`designs/register/`)

### 공통
- 헤더: 뒤로 / "설문 등록" / 임시저장
- 진행바: 기존 앱 스타일 4칸 막대 + 오른쪽 "n / 4"
- 단계마다 큰 제목(24px)
- '다음'이 꺼져 있으면 버튼 안에 이유 표시 (예: "제목을 써 주세요")

### ① 기본 정보 (`Main.dc.html`)
- "템플릿으로 시작하기 ›" 링크 (템플릿 목록은 별도 기획 필요)
- 제목(밑줄 입력, 60자), 설명(선택, 500자)
- 카테고리 8개 칩 → 고른 뒤에만 태그 칩 노출 (카테고리별 추천 6개 + 더보기, 최대 3개)
- 다음 활성 조건: 제목 + 카테고리

카테고리별 추천 태그는 `Main.dc.html` 스크립트의 `SUGGEST` 객체 참고.

### ② 문항 (`Questions.dc.html`)
- 제목 아래 안내: "문항이 5개 이상이면 성실한 응답인지 확인하는 문항이 자동으로 1개 들어가요. 최대 30문항."
- 편집 중인 문항만 펼침, 나머지는 한 줄 요약(Q번호 · 질문 · 답변 방식). 요약을 누르면 펼쳐짐
- 펼친 문항 헤더: 답변 방식 칩(누르면 바텀시트) / 위로 · 아래로 · 복제 · 삭제 버튼
- 질문 입력칸 오른쪽에 사진 버튼 (아래 '보류' 참고)
- 선택형: 보기 목록 + "+ 보기 추가" + "+ 해당 없음" / "+ 기타 (직접 입력)" 버튼
- 하단 "필수" 스위치, "옵션 더보기" 안에 보기 순서 섞기
- 하단 고정: "n문항 · 약 n분 · 1명당 nP" + 다음
- 답변 방식 바텀시트 7종:

| 방식 | 설명 | 비고 |
|---|---|---|
| 하나 고르기 | 보기 중 하나 | 기존 |
| 여러 개 고르기 | 해당하는 것 모두 | 기존 |
| 사진 고르기 | 사진 보기 중 선택 | 신규 · 보류 가능 |
| 5점 척도 | 1~5점 | 기존 |
| 순위 매기기 | 보기를 끌어서 순서 정하기 | 신규 |
| 짧은 주관식 | 한 줄 | 기존 주관식 |
| 긴 주관식 | 여러 줄 | 신규 |

### ③ 대상 · 공개 · 보상 (`Target.dc.html`)
- 누가 응답하나요: 세그먼트 "전체 대학생 / 중앙대생만" (학교 이름은 회원 정보에서)
- 몇 명: −/+ 스테퍼 + 빠른 선택 10/30/50/100명, 아래 "10~300명 · 목표 인원이 모이면 자동으로 마감돼요"
- 등록비 박스: 등록비 / 등록 후 내 포인트
  - 포인트 부족 시 빨간 배경 + "nP 모자라요" + "13명으로"(내 포인트로 가능한 최대) 버튼, 다음 버튼 비활성("인원을 줄여 주세요")
  - "어떻게 계산됐나요? ›" 펼치면: 소요 시간 구간 · 1명당 등록비 × 인원 = 등록비, 응답자 보상과의 차액은 앱 부담 안내, "등록비는 어떻게 정해지나요? ›" → 포인트 정책 페이지
- 언제까지: 3일/7일/14일 + 실제 날짜 "11월 19일 (목) 밤 12시 마감"
- 결과를 누구에게 보여줄까요: 라디오 카드 3개
  - 전체 공개 — 데이터 허브에 올라가요 · 열람될 때마다 40P
  - 중앙대만 공개
  - 비공개 — 나만 볼 수 있어요
  - 안내: 마감 후 응답 5개 이상이면 데이터 허브에 올라가요. 주관식·개인별 답은 비공개
- 경품(선택) 스위치 → 추첨/선착순, 경품 이름, 인원

### ④ 확인하고 등록 (`Review.dc.html`)
- "응답자에게 이렇게 보여요" 카드 미리보기
- 요약 행 4줄(문항 / 대상 / 결과 공개 / 보상) → 누르면 해당 단계로 이동
- 작성자 표시: 세그먼트 "옛썰러 (익명) / 닉네임 공개 (닉네임)", 안내 "학교는 보이지 않아요"
- 등록비 · 등록 후 포인트
- 등록 전에 확인해 주세요: 응답자 보상은 앱이 정하고 지급 / 일찍 마감 시 못 받은 인원만큼 환불 / 소속은 설명에 / **응답 1명이라도 생기면 제목·문항·인원 수정 불가**(빨간 점 강조)
- 등록자만 받는 것: 원본 CSV + 주관식 원문, 열람마다 40P
- 버튼: "150P로 등록하기" (금액 표시)

### ⑤ 등록 완료 (`Done.dc.html`) — 신규 화면
- 캐릭터 점프 애니메이션, "설문을 올렸어요!", "10명이 모이면 자동으로 마감돼요"
- 공유 박스: 링크 복사 / 공유하기
- 버튼: 홈으로 / 내 설문 관리

### ⑥ 내 설문 관리 (`Manage.dc.html`) — 기존 '설문 상세(내 설문)' + '설문 결과' 통합
- 상태 칩(진행 중 · D-n), 제목, 응답 현황(0/10명, 진행바, 마감일·보상)
- 버튼 3개: 링크 공유 / 수정하기 / 응답 마감
- 결과 영역: 응답 없으면 캐릭터 + "첫 응답을 기다리고 있어요" + 공유 버튼
- 결과 공개 범위 "변경" 링크
- 헤더 ⋯ 메뉴: 미리보기 / CSV 받기 / 삭제

### 보류 (비공개 테스트 이후)
- 대표 사진 (`designs/register/later/CardsList.dc.html`, `CardsHome.dc.html`에 카드 표시안 있음)
- 질문에 사진 넣기, 사진 고르기 문항 → 이번에 뺄지 결정 필요 (사진 업로드·저장 필요)

## B. 설문 응답 (`designs/respond/`)

### ① 설문 상세 (`Main.dc.html`)
- 태그(카테고리, "중앙대생만"), 제목, 작성 단체 + 인증 배지
- 요약 카드 한 줄: 포인트 / 소요 시간 / 마감(D-n)
- "응답 대상: 중앙대학교 학생만"
- 선착순 남은 자리 진행바 ("선착순 50자리 남았어요")
- "이런 설문이에요": 설명 + 문항 구성
- 받을 수 있는 보상: 포인트(모두, 자동 적립) / 경품(추첨 n명, 응답 후 응모) 분리
- 개인정보 안내 한 줄, 신고 링크
- 하단 고정 버튼 "1분 만에 10P 받기"

### ② 응답 (`Answer.dc.html`)
- 헤더: X(나가기) / 설문 제목 / "+10P" 칩
- 얇은 진행바(문항 수만큼 칸) + "n / 전체"
- 문항 전환 시 오른쪽에서 슬라이드 인
- 선택형: 큰 버튼 목록, 선택 시 파란 테두리 + 체크
- 5점 척도: 5칸, 선택 시 파랗게 채움, 아래 "전혀 아니에요 · 보통 · 매우 그래요"
- **자동으로 다음 문항으로 넘어가지 않음.** 선택하면 "다음"이 활성화되고 눌러야 이동
- "이전"은 2번 문항부터 노출, 마지막 문항 버튼 "제출하고 10P 받기"
- X → 확인창 "설문을 그만할까요? 지금 나가면 답한 내용이 저장되지 않고 10P도 받을 수 없어요" (나가기 / 계속하기)

### ③ 응답 완료 (`Complete.dc.html`)
- 이모지 대신 캐릭터 점프 + "+10P 적립!" 팝 + 내 포인트 카운트업(177→187)
- 문구: "응답해 주셔서 고마워요" + 설문 목적 한 줄(예: "학생회가 제휴 카페를 고를 때 참고할게요")
- 경품 응모 카드(선택) → 바텀시트: 휴대폰 번호 + 개인정보 제3자 제공 동의(응모 시 필수) → "응모하기"(번호 10자리 이상 + 동의 시 활성) → 카드가 "경품 응모 완료"로 바뀜
- "다른 학생들은 어떻게 답했을까?" + 알림 받기
- 이어서 하기 좋은 설문 2개 추천
- 하단: 홈으로 / 다음 설문 하기

## C. 학교 이름 칩
"우리 학교" 칩은 "중앙대생만"처럼 학교 이름으로 표시 (이미 개발 반영됨). 시안도 맞춰 둠.
- 긴 학교 이름(한국외국어대 등)·약칭은 별도 표 처리 권장, 알약에 최대 너비 + 말줄임
- 회원 정보에 학교가 없으면 "우리 학교 학생만"으로 대체

## D. 확인 필요
1. 응답자 보상(30P)과 등록비(1명당 15P)의 차액을 앱이 부담하는 정책이 맞는지
2. 경품 응모자 목록을 등록자에게 어떻게 전달할지 (신규)
3. 등록자가 마감 전에도 결과를 실시간으로 볼 수 있는지
4. 템플릿 목록 구성
