# 옛썰 개발 보고 ① 회원 기능

> 2026-10-27 · 개발파트 · **2, 3번을 확인해 주시고 5번에 의견을 적어 주세요.**
> 처리 여부 표시: ✅ 반영/확정 · 🔄 진행 중 · ❌ 반영 안 함(이유 적기) · (빈칸) 아직 확인 전

## 요약

회원 기능(가입·로그인)을 완성했고, 아이폰 실기기와 PC에서 모두 동작을 확인했습니다.

**[회원가입]**
- **학생과 단체, 두 가지 경로**로 가입합니다.
  - 학생: 학교 메일 인증 후 가입합니다.
  - 단체: 유형 선택 → 공식 메일 인증 → 단체 정보 입력 → 승인 대기. 운영자가 증빙 링크를 확인해 승인하고, 거절되면 사유를 보고 다시 신청합니다.
- 회원정보는 **전공 계열·입학년도를 선택**합니다 (학과 직접 입력 X). 통계에 쓰기 쉽고 개인이 특정되지 않습니다.
- 학생은 가입 후 **웰컴 500P** 지급 (중복 지급 방지).
- 단체는 응답·포인트 적립이 되지 않습니다.

**[로그인]**
- 이메일 + 비밀번호, 로그인 유지, 비밀번호 찾기, 가입 여부 안내
- 가입 진행 표시, 이어가기, 연결 끊김 재시도

**[아직 임시]** 약관 본문, 첫 화면, 색·글자 크기

## 자세히

**진행:** 약관·학교 이메일 인증·회원정보·가입 완료(500P)·로그인·비밀번호 찾기·**단체 가입** ✅ / 추천인 코드(출시 후)·회원 탈퇴(11월 초) ⏸

**화면 흐름**
- 학생: 유형 선택 → 약관 → 학교 이메일 → 인증번호 → 회원정보 → 가입 완료
- 단체: 유형 선택 → 약관 → 공식 메일 → 인증번호 → 단체 정보 → 승인 대기 → (운영자 승인) → 시작
- 로그인: 이메일 + 비밀번호 (앱을 껐다 켜도 유지) · 비밀번호 찾기: 메일 → 인증번호 → 새 비밀번호

**스크린샷:** [첫 화면] [유형 선택] [학교 이메일] [회원정보] [가입 완료 500P] [단체 정보] [승인 대기] [로그인] ← 이미지 붙여 넣기

## 2. 기획과 달라진 부분 ⭐ (확인 부탁드려요)

| 기획서 | 실제 구현 | 이유 | 처리 여부 |
| --- | --- | --- | --- |
| 학과·학년 직접 입력 | **전공 계열**(예: 사회 → 경영·경제) 선택 + **입학년도** 선택 | 표기가 갈리면 통계를 낼 수 없고, 학교·학과·학번이 겹치면 응답자가 특정됩니다. 결과는 전공 계열까지만 볼 수 있습니다 | |
| 회원은 학생만 | 가입 시 **학생 / 단체** 선택. 단체는 아무 메일 + **운영자 승인**, 응답·포인트는 학생만 | 학생회·동아리·기업이 설문을 올리는 길이 기획서에 없었습니다 | |
| 같은 메일 중복 가입 불가 | 이메일 입력 단계에서 바로 "이미 가입된 메일이에요" | 국내 앱 방식입니다. **남의 메일의 가입 여부를 알 수 있다는 점**이 괜찮은지 확인 부탁드립니다 | |
| 계정 찾기 | **비밀번호 찾기만** 제공, 아이디 찾기 없음 | 학교 메일이 아이디라 따로 찾을 게 없습니다. 휴대폰 본인인증은 출시 후 검토합니다 | |
