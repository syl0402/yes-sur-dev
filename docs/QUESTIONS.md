### D-01. 마일리지가 계속 불어나는 구조 `[DB] [숫자]`

**왜 묻나:** 「3」, 미결정 #1. 응답자 보상은 등록자가 아니라 플랫폼이 새로 만들어 주는 구조입니다. 5분 미만 설문 1건에 50명이 응답하면 등록비 700P가 빠지고 15,000P가 새로 생깁니다. 또 15분 이상 설문에 한 번 응답하면 3,000P를 받는데, 이는 설문 등록 4번에 해당합니다. 마일리지가 너무 쉽게 쌓이면 '응답해야 등록할 수 있다'는 핵심 순환이 깨집니다. 반대로 등록자가 응답자 보상을 직접 부담하게 바꾸면, 가입 직후 500P인 학생은 설문을 거의 올릴 수 없습니다. 어느 쪽을 택하느냐에 따라 마일리지 기록 구조가 달라집니다.

**개발팀 추천안:**
- MVP에서는 원본대로 **등록비 700P를 고정**하고 보상은 플랫폼이 지급합니다.
- 대신 **목표 응답 수 상한을 100명**으로 둬서 설문 1건당 발행량에 한도를 둡니다.
- 모든 금액은 앱 업데이트 없이 바꿀 수 있는 설정값으로 만듭니다. 파일럿 첫 2주의 발행량을 보고 기획팀과 다시 조정합니다.
- 조정 기준은 기획팀이 정해 주세요. 예: "사용자 1인당 주간 순증이 ○○P를 넘으면 보상 단가를 낮춘다."

### D-02. 타깃팅 범위 `[DB]`

**왜 묻나:** 「1-3」은 '학교·학년·전공 타깃팅 무료'를 차별점으로 내세우지만, 설문 작성 항목(F-402)과 데이터 모델(「6」 `surveys`)에는 타깃팅 항목이 없습니다. 타깃 조건은 저장 구조와 '이 설문에 응답할 수 있는가' 판단에 모두 들어가므로 지금 정해야 합니다.

**개발팀 추천안:** MVP에서는 **학교(전체 / 우리 학교만)**와 **과정(전체 / 학부 / 대학원)** 두 가지만 지원합니다. 학년·전공 타깃팅은 다음 단계에서 추가합니다. 대상이 아닌 사용자에게는 설문 목록에서 그 설문이 보이지 않습니다.

### D-03. 추가 보상(기프티콘) 전달 방식 `[DB] [개인정보]`

**왜 묻나:** F-308에서 추가 보상은 '등록자가 직접 지급'합니다. 그런데 등록자가 기프티콘을 보내려면 응답자의 연락처가 필요하고, 이는 「6」의 '응답자 개인정보는 결과에 포함하지 않음' 원칙과 충돌합니다. 연락처를 받으려면 별도 동의, 보관, 파기 절차가 필요합니다.

**개발팀 추천안:**
- MVP에서는 **'추가 보상 있음' 표기와 필터만** 제공합니다.
- 전달 방법(예: "설문 마지막에 오픈채팅 링크로 신청")은 등록자가 설명란에 직접 안내합니다. 앱은 연락처를 수집하지 않습니다.
- 앱 안에서 연락처를 받는 기능(동의 + 별도 보관 + 마감 30일 뒤 파기)은 다음 단계에서 다시 검토합니다.

### D-04. 작성 주체 사칭 방지 `[DB]`

**왜 묻나:** F-402에서 작성 주체(개인·총학생회·학과·기업)를 누구나 고를 수 있으면, 개인이 '총학생회'로 설문을 올릴 수 있습니다. 데이터 열람 필터(F-501)와 신뢰도에도 영향을 줍니다.

**개발팀 추천안:** 기본값은 **'개인'**입니다. 총학생회·학과·기업은 **운영자가 수동으로 승인한 계정만** 고를 수 있습니다. 기관 계정을 원하는 사용자는 운영 이메일로 신청하고, 운영자가 확인한 뒤 계정에 표시를 켭니다.

### D-05. 출시 학교·이메일 도메인 목록 `[DB]`

**왜 묻나:** F-102에서 가입은 '등록된 학교 도메인'만 허용합니다. 그런데 출시 때 어느 학교를 열지 정해지지 않았습니다. 또 한 학교가 도메인을 여러 개 쓰는 경우도 있습니다(예: 학부·대학원 분리, 구·신 도메인).

**개발팀 추천안:**
- 기획팀이 **10/20까지** 출시 학교 목록을 전달해 주세요. 각 학교의 이름, 학생 이메일 도메인 전체, 대학원생 도메인이 다르면 그것도 포함합니다.
- 한 학교에 도메인을 여러 개 등록할 수 있게 만듭니다.
- 목록에 없는 학교 학생에게는 "아직 지원하지 않는 학교입니다"라고 안내합니다.

### D-06. 설문 수정·삭제·조기 마감과 700P 환불 `[DB] [숫자]`

**왜 묻나:** 등록(700P 차감, F-405) 이후 수정, 삭제, 조기 마감 규칙이 없습니다. 응답이 들어온 뒤 문항을 바꾸면 이미 받은 응답과 맞지 않게 됩니다.

**개발팀 추천안:**
- **수정:** 응답이 0건일 때만 가능합니다. 1건이라도 들어오면 마감일 연장만 할 수 있습니다.
- **삭제:** 등록자가 직접 삭제하면 **환불하지 않습니다**. 운영자가 규정 위반으로 내린 경우도 환불하지 않습니다. 운영 측 오류로 내린 경우에만 전액 환불합니다.
- **조기 마감:** 언제든 가능하고 환불은 없습니다.

**답변:**

### D-07. 결과 공개 시점·기본값과 '결과 리턴' 범위 `[DB] [모순]`

**왜 묻나:**
- 결과 공개 설정(F-407)을 언제 하는지 정해져 있지 않습니다. 등록자가 설정하지 않으면 데이터 열람 메뉴가 비게 됩니다.
- 응답자는 제출 직후 전체 응답 분포를 무료로 보는데(F-304), 같은 결과를 데이터 열람에서는 500P를 내고 봅니다(F-503). 비공개 설문(F-408)의 분포를 응답자에게 보여줘도 되는지도 정해야 합니다.

**개발팀 추천안:**
- 공개 범위, 상업적 이용, 원본 다운로드 허용은 **설문 등록 시 함께 입력**하고, **마감되면 자동으로 데이터 목록에 게시**합니다.
- 기본값: **전체 공개 / 상업적 이용 불가 / 원본 다운로드 불가**. 마감 전까지 등록자가 바꿀 수 있습니다.
- 결과 리턴은 **객관식·척도 문항의 분포만** 보여주고, 주관식 답변은 보여주지 않습니다. **비공개 설문은 결과 리턴을 하지 않습니다.**
- 데이터 열람(500P)에서는 문항별 전체 집계를 봅니다.

- 응답자는 '내 응답이 다른 학생에게 열람되고, 상업적으로 쓰일 수도 있다'는 사실을 모른 채 응답할 수 있습니다(F-407).
- '교내 공개'에 학과·학년 정보가 함께 붙으면 응답 수가 적을 때 응답자가 누구인지 추정할 수 있습니다.
- 탈퇴 시 처리 기준도 없습니다.

**개발팀 추천안:** 아래 내용을 약관·개인정보처리방침에 반영해 주세요.
- 가입 약관에 '익명 처리된 응답 결과가 다른 회원에게 공개되고, 등록자가 허용한 경우 상업적으로 이용될 수 있음'을 명시합니다. 응답 시작 화면에도 해당 설문의 **공개 범위와 상업적 이용 여부**를 표시합니다.
- 결과·열람 데이터에는 **응답자의 학과·학년을 넣지 않습니다**. 응답이 **5명 미만**인 설문은 데이터 목록에 공개하지 않습니다.
- **탈퇴 시:** 이메일·닉네임 등 개인정보는 즉시 삭제하고, 이미 제출한 응답은 누구 것인지 알 수 없게 익명으로 남깁니다. 남은 마일리지는 소멸하며 복구할 수 없습니다.
- 설문 등록 화면에 **금지 문항 안내**(건강·정치 성향 등 민감정보, 실명·학번·연락처 등 개인 식별 정보)와 동의 체크를 넣습니다.
