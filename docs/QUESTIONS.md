## 꼭 먼저 정해야 하는 것 (DB 설계에 영향)

### Q1. 마일리지가 너무 많이 풀리는 문제
원본 예시처럼 5분 미만 설문에 50명이 응답하면, 등록자는 700P를 내고 응답자들은 합계 15,000P를 받습니다. 설문 1건마다 약 14,300P가 새로 생깁니다. 응답만 하는 사람은 계속 쌓이고, 등록·열람 비용(700P·500P)이 금방 의미가 없어집니다.

| 선택지 | 내용 | 장단점 |
| --- | --- | --- |
| A | 원본 그대로 (등록 700P 고정, 보상은 플랫폼 지급) | 단순함. 대신 인플레이션 → 파일럿 후 조정 |
| B | 등록 비용 = 응답당 보상 × 목표 응답 수 (등록자가 보상을 부담) | 경제가 균형. 대신 등록 문턱이 높아짐 (5분 설문 30명 = 9,000P) |
| C | 응답 보상을 낮춤 (예: 5분 미만 30P) + 등록 700P 유지 | 단순하고 인플레이션 완화. 응답 동기는 약해짐 |

**개발팀 추천안: A로 시작.** 모든 숫자를 설정값으로 만들어서 파일럿 중 바꿀 수 있게 합니다. 단, B로 갈 가능성이 있다면 지금 알려 주세요. B는 "보상 예약·반환" 기능이 추가로 필요해서 DB 구조가 달라집니다.

### Q13. 학교 이메일이 없는 사용자 (학생회·교내 기관·외부 기업) · 2026-10-26 추가
원본은 "등록된 학교 도메인이 아닌 이메일은 가입 불가"입니다. 그런데 학생회·교내 기관·외부 기업이 설문을 올리는 방법은 "수동 운영"이라고만 되어 있고, 이들이 로그인하는 방법은 정해지지 않았습니다.

**개발팀 추천안:**
- 학생회: 소속 학생이 자기 학교 이메일로 가입하고, 설문 작성 시 작성 주체를 "총학생회"로 선택 (F-402의 작성 주체 칸)
- 교내 기관·외부 기업: 별도 계정 없이 운영자가 대신 설문을 등록
- 이렇게 하면 "대학생만 참여" 원칙을 지키고, 별도 로그인 방식을 만들지 않아도 됩니다

**개발팀 검토 중인 대안 (2026-10-26):** 가입 첫 화면에서 학생 / 학생회·교내 기관 / 외부 기업을 고르게 하고, 기관·기업은 운영자 승인 후 설문 등록만 가능 (응답·적립 불가). 자세한 내용은 `docs/PROGRESS.md`의 "회원가입 경로 여러 개" 메모.
