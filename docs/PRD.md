## 1. 서비스 정의

대학생 인증 기반 **설문 응답 ↔ 마일리지 교환** 플랫폼 + 설문 결과 **데이터 허브**.

**MVP 핵심 흐름**

> 학교 이메일로 가입 → 설문 응답 → 마일리지 적립 → 설문 등록(700P) → 결과 확인·공개 → 다른 사용자가 열람(500P)
> \+ 취향·밸런스 투표로 매일 들어올 이유 제공

## 4. 마일리지 규칙

### 4-1. 원칙

1. 모든 수치는 `point_rules` 표에 저장하고 코드에 숫자를 쓰지 않는다
2. 잔액 = `point_ledger`의 confirmed 합계. 잔액 칸을 따로 두지 않는다
3. 적립·차감은 서버 함수에서만, 하나의 트랜잭션으로
4. 잔액이 음수가 되는 차감은 거부
5. 현금·기프티콘 전환 기능은 만들지 않는다
6. 응답 보상은 **플랫폼이 지급**한다 (등록자가 보상 예산을 미리 내는 방식 아님 → QUESTIONS Q1)
7. 상태: `pending`(예정) → `confirmed`(확정) / `rejected`(반려) / `revoked`(회수)

### 4-2. point_rules 초기값

| --- | --- | --- | --- |

### 4-3. 지급 규칙

- 지급액은 소요시간 구간으로 자동 결정. 등록자가 바꿀 수 없음
- 본인 설문 응답 불가, 본인 밸런스 게시물 투표는 가능하지만 보상 없음
- 같은 설문 1회, 같은 밸런스 게시물 1회 (DB 고유 제약)
- 열람은 한 번 차감되면 재열람 무료

## 5. 성실도 검수 (MVP)

`submit_response` 서버 함수 안에서 계산. 감점 값은 모두 `point_rules`에서 읽는다.

| 규칙 | 기준 | 감점 |
| --- | --- | --- |
| 응답 속도 | 실제 소요시간 < 예상의 30% | −40 |
| 주의 문항 | 지시 응답 오답 | −50 |
| 일자형 응답 | 연속 동일 선택이 80% 이상 (5문항 이상 설문) | −20 |
| 주관식 품질 | 5자 미만 또는 반복 문자 | 문항당 −10 (최대 −30) |

| 점수 | MVP 처리 |
| --- | --- |
| 70점 이상 | 즉시 confirmed |
| 50~69점 | **confirmed + 검토 표시(quality_flags)**. 등록자 검수·72시간 자동 확정은 P1 (Q4) |
| 50점 미만 | rejected, 반려 사유 표시 |

## 7. 데이터 공개 규칙

- 공개 데이터는 **문항별 집계 그래프만**. 개별 응답 다운로드는 출시 후
- 응답 수가 `result_min_count`(5) 미만이면 공개 목록에서 결과를 숨김
- 응답 화면과 약관에 "결과가 집계 형태로 공개될 수 있음"을 고지
- 등록자 CSV에는 무작위 응답 ID, 제출 시각, 답만. 이메일·닉네임 제외, UTF-8 BOM
- 결과 상세(ys-131)는 캡처 방지
