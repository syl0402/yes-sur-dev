## 결정: 가입 첫 화면 학생 / 단체 (2026-10-27)

여러 안(가입 유형 3개 / 사람·단체 분리 / 학생만)을 비교한 뒤 결정. 잡코리아·링커리어처럼 개인회원과 단체회원을 가입 첫 화면에서 나눈다.

| | 학생 계정 | 단체 계정 |
| --- | --- | --- |
| 누가 | 대학생 (교수·교직원이 학생으로 가입하는 건 막지 않음) | 교내: 학생회·동아리·센터·연구실 / 외부: 기업·연구기관 |
| 가입 메일 | 학교 메일만 (도메인 검사) | 아무 메일 (공용 Gmail 가능) |
| 가입 후 | 바로 사용 | **승인 대기** → 운영자가 대시보드에서 상태 변경 → 사용 |
| 입력 | 닉네임, 학과, 과정, 입학년도 | 단체 종류(교내/외부), 단체 이름, 학교(교내만), 증빙 링크, 소개 |
| 웰컴 500P | O | X |
| 응답·적립 | O | X ("인증된 대학생 표본" 가치 보호, 포인트 악용 방지) |
| 설문 올리기 | 포인트로 | 단체 이름으로 (비용은 QUESTIONS Q14) |

- 단체 계정 하나를 임원이 바뀌어도 물려준다 (사람에 묶이지 않음)
- 학생회 임원은 학생 계정 + 단체 계정 두 개 (감수)
- 승인 전에는 로그인은 되지만 "승인 대기 중" 화면만. 거절 시 사유를 보여주고 다시 신청 가능
- 유형·승인 상태는 사용자가 못 바꾼다 (profiles 쓰기 정책 없음, 승인은 운영자만)
- DB: 지금의 `account_type`·`approval_status`를 그대로 쓰고, 단체 정보 칸(종류·이름·증빙 링크·거절 사유)과 단체 가입 서버 함수는 단체 가입 작업 때 새 SQL로 추가. `account_type` 값은 `student / org`로 정리
- 나중에: `submit_response`(응답)에서 `account_type = 'student'`만 허용

출시 후로 미룸: 사진 증빙(사업자등록증), 기업 앱 결제, 승인 알림, 교직원 구분
